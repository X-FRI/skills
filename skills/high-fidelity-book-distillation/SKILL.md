# High-Fidelity Book Distillation

## Purpose

This skill turns non-fiction books into structured knowledge systems.

The goal is not to produce a short promotional summary. The goal is to reconstruct the book's argument, preserve its conceptual structure, identify its evidence, separate facts from interpretation, expose limitations, and guide the reader back to the original text when deeper reading is useful.

Use this skill for non-fiction books such as investing, personal finance, psychology, business, management, productivity, science, philosophy, history, decision-making, health, education, and practical life strategy.

The output should help the user understand the book well enough to discuss it, apply it, critique it, and decide which original sections are still worth reading.

## Core Principle

Do not summarize the book as a list of topics. Reconstruct the book as a system of claims, reasons, evidence, examples, concepts, and applications.

A high-fidelity book guide should answer:

- What problem is the book trying to solve?
- What does the author want the reader to believe?
- What misconception is the author correcting?
- What are the main claims?
- What evidence, cases, history, or reasoning supports those claims?
- Which claims are empirical, interpretive, motivational, anecdotal, or speculative?
- What concepts must the reader understand?
- What should the reader do differently after reading?
- What are the limits, risks, outdated parts, or context-dependent parts?
- Where should the reader return to the original book for verification or deeper reading?

## Scope and Boundaries

This skill is for source-guided non-fiction book distillation, argument reconstruction, cross-book comparison, and practical framework extraction.

Do not reproduce long passages from copyrighted books. Do not create a chapter-by-chapter rewrite that can substitute for the original. Do not fabricate page numbers, chapter titles, source locations, quotes, or evidence.

If the user asks for a guide that makes the original book unnecessary, reframe the task. You may produce a high-fidelity learning guide that transfers the main knowledge, argument structure, concepts, and practical implications, but you must not recreate the book or imply that the guide fully replaces the original.

## Workflow

### 1. Identify the Reading Goal

First infer what the user wants to accomplish.

Common goals include:

- Quick orientation before reading.
- High-fidelity understanding without reading every page.
- Chapter-by-chapter study.
- Practical application.
- Cross-book comparison.
- Critical evaluation.
- Reading plan.
- Source-guided review.
- Knowledge-base construction.

If the goal is unclear, ask one concise clarification question. Do not over-ask if the user has already provided enough context.

Useful clarification questions:

- "Do you want a short brief, a detailed learning guide, or a practical action manual?"
- "Should the output focus on understanding the author's argument or applying the ideas?"
- "Should I treat this as a neutral summary or a critical evaluation?"
- "Do you want source pointers by chapter, section, page, or Kindle location if available?"

### 2. Inspect the Available Source

Identify what source material the user has provided.

Possible source types:

- Full book text.
- Long excerpt.
- Table of contents.
- Selected chapters.
- User highlights.
- User notes.
- Book title only.
- Multiple books for comparison.

If the user provides source text, rely primarily on that text.

If the user provides only a title and asks for exact detail, state that the output will rely on general knowledge unless the user provides the text, table of contents, or notes.

If the source has no page numbers, use chapter titles, section titles, subsection titles, or distinctive topic anchors as source pointers.

If the source includes Kindle locations, EPUB locations, page numbers, or section IDs, use them when relevant.

### 3. Classify the Book Type

Classify the book before distilling it. The book type determines what to extract.

#### Evidence-Driven Books

Examples: investing, economics, science, medicine, public policy, history.

Extract:

- Central thesis.
- Evidence chain.
- Data quality.
- Causal claims.
- Competing explanations.
- Counterarguments.
- Scope conditions.
- Practical implications.

For investment and finance books, separate:

- Market history.
- Investment theory.
- Empirical evidence.
- Behavioral claims.
- Product recommendations.
- Tax assumptions.
- Country-specific rules.
- Actionable portfolio principles.

#### Idea-Driven Books

Examples: wealth mindset, entrepreneurship, leadership, productivity, personal development.

Extract:

- Core mental model shifts.
- Repeated distinctions.
- Memorable frameworks.
- Anecdotes versus durable principles.
- Inspirational claims versus operational claims.
- Simplifications and overstatements.
- Safe applications.

#### Method-Driven Books

Examples: books that teach a process, system, operating method, or practical framework.

Extract:

- Steps of the method.
- Required inputs.
- Expected outputs.
- Preconditions.
- Failure modes.
- Correct-use examples.
- Misuse cases.
- Adaptation rules.

#### Behavior-Driven Books

Examples: psychology, money behavior, habits, decision-making, risk, self-control.

Extract:

- Biases and emotional patterns.
- Common failure modes.
- Behavioral interventions.
- Decision rules.
- Environmental design.
- Why knowledge fails to change behavior.
- How to prevent self-sabotage.

#### Story-Driven Non-Fiction

Examples: memoirs, biographies, company histories, case-based books.

Extract:

- What the story is meant to prove.
- Which lessons generalize.
- Which lessons depend on luck, timing, survivorship, or context.
- What the reader should not overlearn from the story.

### 4. Choose the Output Mode

Select the output mode based on the user's goal.

#### One-Page Brief

Use when the user wants quick orientation.

Include:

- One-sentence thesis.
- The problem the book solves.
- Three to seven core ideas.
- Strongest insight.
- Main caveat.
- Whether the book is worth reading.

#### High-Fidelity Learning Guide

Use as the default for serious book distillation.

Include:

- Thesis.
- Problem.
- Argument map.
- Core concepts.
- Key claims and evidence.
- Practical principles.
- Critical evaluation.
- Source location pointers.
- Self-test questions.

#### Chapter Study Guide

Use when the user wants to study the book closely.

For each chapter or major section, extract:

- Core question.
- Main claim.
- Reasoning.
- Evidence.
- Examples.
- Concepts.
- Practical takeaway.
- Caveat.
- Original reading pointer.

#### Comparative Synthesis

Use when the user provides several books.

Compare:

- Thesis of each book.
- Assumptions.
- Evidence quality.
- Shared principles.
- Conflicts.
- Best use case.
- Weaknesses.
- Integrated framework.
- Recommended reading order.

#### Application Manual

Use when the user wants to act on the book.

Include:

- Decision rules.
- Checklists.
- Workflows.
- Warning signs.
- Review questions.
- Thirty-day application plan.
- Misuse cases.

#### Critical Evaluation

Use when the user wants judgment rather than neutral summary.

Include:

- What the book gets right.
- What it overstates.
- Which claims are well-supported.
- Which claims are anecdotal.
- What is outdated.
- What the book leaves out.
- What to apply.
- What to ignore or treat carefully.

### 5. Build the Argument Map

Before writing the final answer, reconstruct the book's internal logic.

Identify:

- The opening problem.
- The author's central answer.
- The sequence of arguments.
- The main concepts.
- The key evidence.
- The recurring examples.
- The practical recommendations.
- The final implication.

Do not simply stack chapter summaries. Explain how the chapters connect.

A strong argument map should show progression:

- The book starts by correcting a misconception.
- It introduces a model or distinction.
- It supports the model with evidence, stories, or cases.
- It tests or rejects competing approaches.
- It derives practical rules.
- It ends with implications for the reader.

### 6. Extract Chapter Atoms

When processing a full book, long excerpt, or detailed table of contents, extract chapter atoms first.

For each chapter or major section, identify:

- Core question: What problem does this section address?
- Claim: What does the author want the reader to believe?
- Reasoning: How does the author support the claim?
- Evidence: What data, history, cases, studies, or examples appear?
- Concept: What terms or models are introduced?
- Takeaway: What should the reader remember?
- Application: What should the reader do differently?
- Caveat: What may be overstated, incomplete, outdated, or context-specific?
- Source pointer: Where should the reader return in the original book?

Use these atoms to produce the final synthesis.

### 7. Separate Knowledge Types

Clearly distinguish different kinds of content.

Use these categories internally and, when useful, explicitly in the output:

- Fact: A claim backed by observable data, dates, studies, market history, or documented events.
- Argument: The author's interpretation of facts.
- Principle: A general rule derived from the book.
- Story: An example used to illustrate or persuade.
- Advice: A recommended action.
- Speculation: A claim about the future or a weakly evidenced claim.
- Context-bound claim: A claim that depends on country, tax system, time period, market structure, culture, or personal situation.

This distinction is essential. Many bad summaries fail because they present anecdotes as evidence or author opinion as fact.

### 8. Reconstruct Concepts Before Giving Advice

Do not jump directly from the book to "what you should do."

First explain the book's concepts in plain language. Then explain how those concepts produce the author's advice.

For example, in an investment book, do not merely say "buy index funds." Explain:

- What market efficiency means.
- Why active management struggles after fees and taxes.
- Why diversification lowers idiosyncratic risk.
- Why behavior matters.
- Why long-term asset allocation matters more than stock picking.
- Under what conditions the conclusion applies.

### 9. Add Source Location Pointers

Use source location pointers to guide the user back to the original book.

A source pointer is not a long quotation. It identifies where the reader can find the original discussion.

Use source pointers for:

- The book's central thesis.
- Major concept definitions.
- Important empirical claims.
- Historical episodes or cases.
- Practical rules derived from specific chapters.
- Controversial or easily misunderstood claims.

Do not attach a pointer to every sentence. Prefer placing pointers after a major claim or at the end of a section.

Preferred formats:

- `Source pointer: Chapter 7, "Fundamental Analysis and Efficient Market Theory."`
- `Source pointer: Chapter 1, sections "The Firm-Foundation Theory" and "The Castle-in-the-Air Theory."`
- `Source pointer: Chapter 10, near the discussion of overconfidence and loss aversion.`
- `Source pointer: Part IV, Chapters 12–15, especially the practical portfolio construction sections.`
- `Source pointer: Chapter 14; Kindle location 6200–6450 if available.`
- `Source pointer: User-provided excerpt, section titled "A Life-Cycle Guide, use chapter titles, section titles, subsection titles, and distinctive topic anchors.

If editions may differ, avoid relying only on page numbers. Prefer chapter and section references.

If the idea is synthesized from several parts of the book, write:

`Synthesized from: Chapters 7–15.`

If the idea is a practical implication derived from the book but not stated directly by the author, write:

`Derived from: Chapters 12–15.`

Use this distinction:

- `Source pointer:` for direct original locations.
- `Synthesized from:` for cross-chapter synthesis.
- `Derived from:` for practical advice inferred from the book's principles.

Example section:

```markdown
### Why the Book Distrusts Stock Picking

The book argues that both technical analysis and fundamental analysis have serious limits. Technical analysis often mistakes random price movement for meaningful patterns. Fundamental analysis is more grounded, but analysts still struggle to forecast future earnings accurately, and active managers often fail to beat broad indexes after fees, taxes, and trading costs.

Original reading pointers:
- Chapter 5, "Technical Analysis and Fundamental Analysis"
- Chapter 6, "Technical Analysis and the Random Walk Theory"
- Chapter 7, "Fundamental Analysis and Efficient Market Theory"
```

The goal of source pointers is verification and selective original reading. They should improve trust and navigability without turning the guide into a copyrighted substitute.

### 10. Add Critical Evaluation

A high-fidelity guide must not worship the book.

Evaluate:

- Where the book is strongest.
- Where the book is weak.
- Which claims are supported by evidence.
- Which claims rely mainly on anecdotes.
- Which claims are outdated.
- Which claims are country-specific or market-specific.
- What the reader might misunderstand.
- What the book leaves out.
- What would change the conclusion.

For practical books, explicitly identify misuse cases.

### 11. Convert Knowledge Into Use

After explaining the book, convert it into usable tools.

Possible outputs:

- Decision rules.
- Checklists.
- Practice plans.
- Review questions.
- Warning signs.
- Mental models.
- Implementation steps.
- Mistake lists.
- Concept glossary.
- "If you only remember ten things" section.

For financial, legal, medical, or health-related books, keep the advice general unless the user provides the required personal context. State that the output is educational and not individualized professional advice.

Choose the structure that matches the user's request.

## Financial Book Handling

When distilling financial or investment books, always separate:

- Personal finance behavior.
- Investment theory.
- Market history.
- Product recommendations.
- Tax rules.
- Country-specific rules.
- Author opinion.
- Empirical evidence.
- Actionable rules.

Do not present a book's investment recommendation as universally correct. Translate it into conditional rules.

Example:

```markdown
Low-cost index funds can be suitable as a default core holding for many long-term investors because they provide broad diversification and low fees. This does not remove market risk, and it does not guarantee positive returns over short horizons.

Derived from: Chapters on efficient markets, indexing, lifecycle allocation, and practical portfolio construction.
```

If the user asks for personalized investment advice, check whether the required personal variables are known:

- Capital size.
- Time horizon.
- Liquidity needs.
- Risk tolerance.
- Tax situation.
- Country or market.
- Existing assets and liabilities.

If these variables are missing, avoid specific allocation advice or ask for the missing context.

## Handling Long Books or Large Excerpts

If the source is too long for one response, propose a staged workflow.

Use this batch process:

1. Process the table of contents and build a book map.
2. Process chapters or parts in batches.
3. Extract chapter atoms for each batch.
4. Build a cross-chapter synthesis.
5. Produce a final high-fidelity guide.
6. Add original reading pointers.
7. Add a practical application framework.
8. Add critical evaluation and self-test questions.

For each batch, output:

```markdown
## Section Covered

## Core Question

## Main Claims

## Evidence and Examples

## Concepts Introduced

## Practical Takeaways

## Caveats

## Links to Earlier Sections

## Original Reading Pointers
```

Do not attempt to cover every sentence. Preserve argument structure, not surface detail.

## Prompt Templates for the User

When useful, offer the user reusable prompts.

### High-Fidelity Single-Book Guide

```text
Turn the following book into a high-fidelity learning guide. Do not reproduce the book. Reconstruct the author's argument in your own words. Include the book's central thesis, problem, argument map, core concepts, major claims, evidence, practical principles, limitations, and self-test questions. Separate facts, author opinions, anecdotes, and actionable rules. Add original reading pointers by chapter, section, or topic anchor.
```

### Chapter-by-Chapter Study Guide

```text
Create a chapter-by-chapter study guide. For each chapter, extract the core question, main claim, reasoning, evidence, examples, concepts, practical takeaway, caveat, and original reading pointer. Then synthesize the whole book into one integrated framework.
```

### Fast Reading Plan

```text
Based on this table of contents, create a fast reading plan. Identify which chapters to read deeply, skim, or skip. Explain why. Then give me a two-hour reading route and a thirty-minute emergency version.
```

### Multi-Book Comparison

```text
Compare these books as a knowledge system. Identify each book's thesis, assumptions, evidence quality, strongest ideas, weak points, overlaps, conflicts, and best use case. Then integrate the strongest ideas into a practical framework. Include original reading pointers for the most important sections.
```

### Practical Action Manual

```text
Convert this book into an action manual. Extract decision rules, checklists, workflows, warning signs, review questions, and a thirty-day application plan. Include limits, misuse cases, and source pointers to the original sections behind each major rule.
```

### Critical Evaluation

```text
Evaluate this book critically. What does it get right? What does it overstate? Which claims are empirical, anecdotal, motivational, or outdated? What should a reader apply, and what should a reader treat cautiously? Add source pointers for the claims being evaluated.
```

## Example: Comparing Three Money Books

When comparing `A Random Walk Down Wall Street`, `Rich Dad Poor Dad`, and `The Psychology of Money`, use this framing:

`A Random Walk Down Wall Street` is the investment-method foundation. It argues that most investors cannot reliably beat broad market indexes after fees, taxes, and trading costs, so low-cost diversified index investing is the most reliable strategy for many ordinary long-term investors.

`Rich Dad Poor Dad` is the wealth-mindset foundation. It argues that people should understand assets, liabilities, cash flow, financial education, and the limits of relying only on wages. Its value is conceptual and motivational, not primarily empirical.

`The Psychology of Money` is the behavior foundation. It argues that financial success depends heavily on patience, humility, savings behavior, risk management, and the ability to avoid self-sabotage.

The integrated lesson is:

- Build income and savings capacity.
- Understand assets, liabilities, and cash flow.
- Invest through low-cost diversified systems.
- Avoid trying to predict short-term market movement.
- Protect the system from behavioral mistakes.
- Keep enough flexibility and safety margin to survive bad periods.

Treat the books differently:

- Use `A Random Walk Down Wall Street` for evidence-based investment method.
- Use `The Psychology of Money` for behavior and risk discipline.
- Use `Rich Dad Poor Dad` for mindset shifts, while checking its claims against tax law, leverage risk, market conditions, and local context.

## Style Rules

Write in clear, ordinary English unless the user requests another language.

Prefer precise explanation over motivational phrasing.

Avoid empty phrases such as:

- "This book is a must-read."
- "It provides valuable insights."
- "In today's fast-paced world."
- "The author masterfully explores."
- "This comprehensive guide."

Use concrete phrasing:

- "The book's strongest claim is..."
- "The argument depends on..."
- "This is useful when..."
- "This becomes risky when..."
- "The reader should not confuse..."
- "The author supports this with..."
- "The book does not fully address..."

Do not over-compress. The goal is not the shortest possible summary. The goal is the smallest useful version that preserves the book's knowledge structure.

Do not over-polish into promotional prose. Keep the tone analytical, calm, and practical.

## Quality Constraints

Before finalizing the output, check:

- Does the output explain the book's argument rather than merely list topics?
- Are the author's claims separated from evidence and interpretation?
- Are anecdotes treated as anecdotes?
- Are practical rules conditional rather than absolute?
- Are country-specific or time-specific claims identified?
- Are copyrighted passages avoided?
- Are source pointers included where they help verification?
- Are page numbers, quotes, and locations not fabricated?
- Does the output help the user decide what to do differently?
- Does the output say what still requires reading the original?
- Is the prose clear, ordinary, and precise?
- Is the output useful without pretending to be the book itself?

## Final Response Behavior

If the user asks for a SKILL.md, return the complete file content in a single markdown code block.

If the user asks for a book guide, produce the guide directly.

If the user asks for a shorter or longer version, adjust the compression level while preserving the core argument, source pointers, and caveats.

If the source is insufficient, say exactly what is missing and proceed only within the available evidence.
